## データフロー

### 取引登録

```
Add page
  → TransactionForm.submit
    → useBudgetStore.addTransaction(input)
      → transactions.push({ ...input, id, createdAt })
    → router.push("/today")
    → persist automatically triggered
```

### 月次サマリの計算

```
月の家計簿を開く
  → useBudgetStore(state => state.getMonthlyTotals(selectedMonth))
    → filter transactions by month
    → group by category.type
    → sum expense / income
    → return { expense, income, balance }
```

### 固定費適用

```
User opens app / clicks "今月の固定費を適用"
  → useBudgetStore.applyFixedCostsForMonth("2026-06")
    → for each active FixedCost:
      → if already applied for this month: skip
      → construct Transaction (date = YYYY-MM-{clamped payment_day})
      → addTransaction({ ..., isAutoGenerated: true, fixedCostId })
      → mark appliedFixedCostMonths[fixedCostId].push("2026-06")
```

## 重要ロジック詳細

### `applyFixedCostsForMonth(monthKey)`

```ts
function applyFixedCostsForMonth(monthKey: string) {
  const [year, month] = monthKey.split("-").map(Number);
  const daysInMonth = new Date(year, month, 0).getDate();

  for (const fc of fixedCosts.filter(f => f.active)) {
    const alreadyApplied = appliedFixedCostMonths[fc.id]?.includes(monthKey);
    if (alreadyApplied) continue;

    const day = Math.min(fc.paymentDay, daysInMonth); // 2/30 → 2/末
    const date = `${monthKey}-${String(day).padStart(2, "0")}`;

    addTransaction({
      categoryId: fc.categoryId,
      amount: fc.amount,
      date,
      memo: fc.label ?? "固定費",
      isAutoGenerated: true,
      fixedCostId: fc.id,
    });

    appliedFixedCostMonths[fc.id] = [...(appliedFixedCostMonths[fc.id] ?? []), monthKey];
  }
}
```

**Idempotency**: 同月に 2 回呼ばれても重複計上しない。

### 削除時の関連 Transaction 扱い（Phase 1 で決定）

現状: **removeCategory はカテゴリだけ消し、Transaction の categoryId は残す**（display 時に "削除済カテゴリ" と表示）。将来的に UX 決定次第で移す。

### 収支の集計

```ts
function getMonthlyTotals(monthKey: string) {
  const txs = getMonthlyTransactions(monthKey);
  let expense = 0, income = 0;
  for (const t of txs) {
    const cat = categories.find(c => c.id === t.categoryId);
    if (cat?.type === "income") income += t.amount;
    else expense += t.amount; // 削除済カテゴリは支出扱い
  }
  return { expense, income, balance: income - expense };
}
```

### 円グラフ用のカテゴリ集計

```ts
function getMonthlyByCategory(monthKey: string) {
  const txs = getMonthlyTransactions(monthKey);
  const map = new Map<string, number>();
  for (const t of txs) {
    map.set(t.categoryId, (map.get(t.categoryId) ?? 0) + t.amount);
  }
  return Array.from(map.entries())
    .map(([categoryId, total]) => ({
      category: categories.find(c => c.id === categoryId) ?? DELETED_CATEGORY,
      total,
    }))
    .filter(x => x.category.type === "expense")
    .sort((a, b) => b.total - a.total);
}
```

## ステート遷移（Category / Transaction）

```
[Category]
  new → active → (削除) → 削除済 (orphan、Transaction は categoryId で参照残る)

[Transaction]
  new → committed
       ↓ (edit)
       committed
       ↓ (remove)
       gone

[FixedCost]
  new → active ↔ inactive → deleted
                    ↓
                    生成した Transaction は残る
```

## モバイル UI 詳細

### ホーム・日次目標・分析

- `/` は元の表紙イラストを使ったタイトル画面。「家計簿を開く」で `/today` へ進み、家計簿名をタップすると表紙へ戻る。
- ホーム（`/today`）は今日の残り予算または超過額とミニかなこを1枚にまとめる。週間予算、はなまるカレンダー、月の家計簿、目的別の貯金はタップで開く。新しい取引や日次目標の保存後はホームへ戻る。
- スマホの主要画面は幅320px、高さ568pxを基準とする。月、衣装、履歴、カテゴリなどの切り替えにはボタンを使う。文字の拡大やソフトウェアキーボードの表示時は、必要な範囲を通常のスクロールで操作できる。
- `/settings/daily-budget` で0円以上の整数を設定する。目標はローカル日付と金額の組を時系列に保存し、設定日から適用する。同日の再設定は上書きする。Zustand の保存形式 v4 は既存の `kanako_kakeibo` キーを使い、v1〜v3 の既存データを引き継ぐ。
- 日次支出は取引の日付ごとに合算し、収入・固定費カテゴリ・固定費から自動生成した取引を除く。目標のある日が目標額以内で終わると、翌日から `/calendar` に達成印を表示する。記録上の支出が0円の日も対象。取引の訂正時は該当日を再集計する。日付をタップすると詳細を開き、`/history?date=YYYY-MM-DD` に移動できる。
- 週間予算は月曜から日曜までの目標額の合計。目標を設定した日以降の変動費を集計する。前日までの目標額と支出の差を今日の予算に加減し、月曜に繰り越しをリセットする。目標を週の途中で変更した場合は変更日以降の目標額を合計に反映する。はなまるは引き続き日ごとの目標で判定する。
- ミニかなこは表紙のイラストを参照した5枚の透過 WebP を使用する。最初は中央の段階から始め、日が終わるたびに目標達成で1段階上がり、超過で1段階下がる。当日の超過は暫定で1段階反映する。
- `MonthlyInsights` は `selectedMonth` を基準に直近 6 か月を `shiftMonthKey` で作り、`getMonthlyTotals(monthKey)` から収入 / 支出 / 収支を算出する。
- 貯金率は `balance / income * 100`。収入が 0 の月は `--` 表示として、ゼロ除算しない。
- 月次推移グラフは recharts の `BarChart`。ピンクを支出、グリーンを収入に固定し、データは localStorage 由来の store だけから読む。

### ミニかなこの着せ替え

- ホームの「着せ替え」から `/wardrobe` を開く。ボタンで衣装を選び、中央に1着ずつ表示する。前日までのはなまるが3日・7日・10日・14日・21日連続すると、順に「桜のおでかけ服」「星空のドレス」「リネンの街歩き」「庭園のティードレス」「ベルベットの夜会服」が解放される。導入前の目標履歴から達成した連続日数も集計する。
- 最初はエプロンを含む3着を表示する。3着目までそろうと次の3着を表示し、今後の衣装も3着ずつ同じ順番で表示する。未解放の衣装は番号とグレーのシルエットで予告する。
- 解放済みの衣装と着用中の衣装を localStorage に保存する。連続記録が途切れても、解放済みの衣装は着用できる。各衣装に予算状況に応じた5段階のイラストがあり、同じ段階では頭の高さと裾の位置をエプロンに合わせる。
- タイトル画面のかなこを1秒以内の間隔で5回続けてタップすると、デバッグモードで着せ替え画面を開き、全衣装を試着できる。デバッグの着用状態はタブのメモリに保持する。「デバッグを終了」またはページの再読み込みで、通常の解放状況と着用中の衣装に戻る。

### 履歴の編集・よく使う支出・目的別の貯金

- 履歴の取引をタップして金額、日付、カテゴリ、メモを編集する。登録画面と同じ入力欄を使い、保存時に取引のIDと固定費の自動計上情報を引き継ぐ。
- 登録画面の「よく使う支出」には、入力した金額、カテゴリ、メモを保存できる。呼び出すと同じ項目が入力され、表示中の日付で取引を確認して保存する。
- ホームの「目的別の貯金」で複数の目標と積み立てを管理する。積み立ては貯金目標に記録し、取引の収支と日・週の予算には加算しない。目標額に到達したときは、着用中の衣装のミニかなこがお祝いする。
- 同じ端末で旧版の画面が残っている場合に備え、よく使う支出と貯金目標の最新の内容を補助キーにも保存する。旧版が本体を上書きした場合は、旧版で変更した取引と補助キーの内容を v4 に引き継ぐ。

### PWA アイコン

- PWA / Apple touch / favicon の各アイコンは `public/images/kanako-title.jpg` の顔部分から生成する。
- 通常アイコンは `public/icons/kanako-icon-192.png` / `public/icons/kanako-icon-512.png`、maskable は余白多めの `public/icons/kanako-maskable-512.png` を使う。
- `public/manifest.webmanifest` は GitHub Pages の basePath でも壊れないよう、icon / start_url / scope を相対パスで定義する。`layout.tsx` の metadata では production 時だけ `/KANAKO_KAKEIBO` を付ける。

### 公開版の更新通知

- 本番の静的ビルド時に生成した版の識別子を、クライアントと `version.json` に埋め込む。表示中のクライアントは起動時、画面復帰時、オンライン復帰時、表示中の定期確認で公開中の版と照合する。
- 新しい版が見つかると確認ダイアログを表示する。「今すぐ更新」で現在のページを再読み込みし、「あとで」で開いているページでの通知を閉じる。家計簿は同じ localStorage キーから読み込む。
- GitHub Pages の公開時は、直近3件の成功した公開から取得できるハッシュ付きの JavaScript と CSS を残す。HTML、画面遷移用のデータ、`version.json` は最新ビルドを配信する。
- 本番のHTMLは、アプリ起動前から同一オリジンの JavaScript の読み込み失敗を検知する。読み込み直しのボタンはキャッシュを避けるクエリを付け、同じページを開く。操作中の例外でも端末の保存データを使って開き直せる。

## スタイル方針

- Tailwind utility class 直接
- 共通色は `globals.css` のカスタムプロパティを使う。生成りの紙色をベースに、ローズを主要アクション、セージを週間予算、ゴールドを表紙や小さなアクセントに使う。
- 表紙は元のイラストを細い額縁に収め、タイトルを画像の下に置く。ホームでは今日の金額を最も大きく表示し、花のモチーフは表紙やはなまるを中心に使う。
- 収支の色分け
  - 支出: `text-rose-600 bg-rose-50 border-rose-200`
  - 収入: `text-emerald-600 bg-emerald-50 border-emerald-200`
  - 固定費バッジ: `text-amber-700 bg-amber-100`
- 表紙、見出し、本文、金額には共通の日本語ゴシック体を使う。端末のフォントを使い、文字の大きさと太さで見出しを区別する。
- 金額は `tabular-nums` で桁を揃える。

## セキュリティ・プライバシー

- Phase 1〜2: **サーバに一切送らない**、localStorage のみ
- Phase 3: Firebase 導入時に暗号化なし（Firestore 依存）
- 個人情報は扱わない（名前 = "かなこ" 等はローカル）
- レシート画像は Phase 3 で Firebase Storage / user 別 bucket

## パフォーマンス

- Zustand selector で subscribe を最小化
- 月次集計は selector で `useMemo` 相当（selector 内でメモ化）
- Transaction が数千件を超えたら indexeddb 移行検討（Phase 2 後半）

## 将来の拡張ポイント

- **予算機能**: Category に `monthlyBudget?: number` を追加、Home で消化率を表示
- **タグ**: カテゴリと直交する tag システム（"必要", "浪費" 等）
- **繰り返し支出**: 固定費とは別の「隔週」「毎週金曜」等の repeat
- **サブアカウント**: 「かなこ」「かずき」等の分離（Phase 4）

## 制約

- iOS Safari の date input UI はカスタマイズ困難 → 早期に react-day-picker 等を導入検討
- localStorage 5-10MB 制限 → 数年分のデータで到達する可能性
- SSR で store のデータを描画すると hydration mismatch → **client only page** にする（`"use client"`）
